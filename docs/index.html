SSH, tunnels and SFTP over a local encrypted vault.

Citadel stores hosts, keys, tunnels and trusted host keys in one file encrypted with a key derived from your password. There is no Citadel account and no Citadel server. Replication is optional and goes to an S3-compatible bucket, a WebDAV share or a Git repository that you control. The core is Rust; the interface is a Tauri v2 application on the system webview.

01Architecture

The workspace is split into crates with one responsibility each. The desktop application is a thin layer that owns sessions and the lock lifecycle and forwards bytes to the webview. Every crate below builds and tests without the webview.

02Security

The vault file can be copied to an untrusted disk without exposing its contents. The password is the only secret; it is never stored. A random 256-bit data key encrypts every record and is itself stored only in wrapped form.

Cryptography

ItemSpecification
Password KDFArgon2id, version 0x13, m = 65536 KiB, t = 3, p = 4, 32-byte output, 32-byte salt from the OS CSPRNG. Parameters are stored in the header and bounded on read (m ≤ 2 GiB, t ≤ 64, p ≤ 64) so a crafted file cannot exhaust memory.
Key wrapXChaCha20-Poly1305 over the 32-byte data key, 24-byte random nonce, associated data = header bytes 0..81.
RecordsXChaCha20-Poly1305, fresh 24-byte random nonce per write. Associated data = "citadel.record.v1" ‖ 0x00 ‖ table ‖ 0x00 ‖ id. After decryption the embedded id must equal the storage key, so ciphertexts cannot be moved between records or tables.
SerializationMessagePack. Buffers are sized before encoding and encrypted in place so no reallocated plaintext copies are left on the heap.
Randomnessgetrandom (OS CSPRNG) for salts, nonces, data keys and record ids.
Storageredb, ACID, crash-safe. The file is created with mode 0600 and a new parent directory with 0700 on Unix; redb holds an exclusive lock while the vault is open.

Memory

  • Passwords, private keys and passphrases are held in secrecy types; decrypted buffers and the derived keys are Zeroizing.
  • Argon2 runs in a caller-provided 64 MiB arena that is zeroized after derivation. The library's own allocator path frees that memory without clearing it.
  • The key-encryption key exists only for the duration of the unwrap. The data key lives only inside the cipher state, which zeroizes it when dropped.
  • Locking, manually or from the idle watchdog, drops the cipher state. Every operation on a locked vault fails until the next unlock.

SSH

ItemBehaviour
Implementationrussh 0.64 with the ring crypto backend. No OpenSSL and no libssh2. ring itself contains C and assembly; there are no other native cryptographic dependencies.
Host keysChecked before authentication on every hop. The bundled verifier reads OpenSSH known_hosts in strict or trust-on-first-use mode and reports changed keys with the offending line. Trusted keys can also be stored as encrypted vault records.
IdentitiesEach host names one identity: an embedded key, a key held by an external agent (matched by SHA-256 fingerprint), a password, or keyboard-interactive. Only that identity is offered to the server.
Agent forwardingCitadel answers the forwarded agent channel itself. REQUEST_IDENTITIES returns only the host's assigned key; SIGN_REQUEST is honoured only for that key's blob; every other message gets FAILURE. Hosts that authenticate with a password expose an empty agent.
RSArsa-sha2-512 or rsa-sha2-256 as negotiated; rsa-sha2-512 when the server does not advertise server-sig-algs.
ImportsRecords from an imported .ctdl are validated like hand-entered ones. Agent forwarding and tunnel autostart are switched off and trusted host keys are dropped, so a bundle from someone else cannot open connections or pin host keys on unlock.
UnlockAttempts are serialised; each consecutive failure doubles the delay, from 0.5 s up to 30 s.
AuditA local report grades the vault from A to F and lists DSA and short RSA keys, password logins, agent forwarding, tunnels bound beyond loopback, plaintext sync endpoints, disabled auto-lock and below-target KDF cost.

Limits. A process that can read Citadel's memory while the vault is unlocked can read its keys. Zeroization is best-effort: moved structs may leave stack copies, and third-party buffers (zstd during export, the SSH stack, the webview) are outside Citadel's control. Memory is not locked against swap. See SECURITY.md.

03Tunnels and sessions

Link supervisor

  • A link supervises one SSH connection; terminals, tunnels, SFTP and telemetry can share it.
  • Keepalive heartbeat at the host's interval (default 15 s). Three unanswered probes end the session.
  • Redial with exponential backoff: 500 ms base, doubling, 30 s cap, ±20 % jitter. The attempt counter resets after 60 s of uptime.
  • The dial function runs on every attempt, so credentials are resolved fresh each time. If they cannot be resolved, for example because the vault is locked, the attempt fails and backoff continues.

Forwarding

  • -L and -D listeners are bound once and stay bound across reconnects. Connections that arrive during an outage wait up to 20 s for the link.
  • -R forwards are re-requested on every new session and cancelled when the tunnel stops.
  • Dynamic forwarding implements SOCKS5 CONNECT without authentication, for IPv4, IPv6 and domain names. Bind it to loopback.
  • Per-tunnel counters: active and accepted connections, failures, bytes in each direction.

Jump chains

  • Each hop is a full SSH session carried inside a direct-tcpip channel of the previous one. Nothing is spawned and no ProxyCommand is used.
  • Host keys and credentials are checked per hop.
  • Losing a bastion ends every session tunnelled through it; disconnecting a chained session also disconnects its bastions.

SFTP

  • 32 KiB requests with 64 in flight per transfer.
  • Downloads write to <name>.citadel-part, fsync, then rename.
  • Uploads and edits write a hidden sibling opened with O_EXCL, preserve the file mode, use fsync@openssh.com when offered, and replace the target with posix-rename@openssh.com.
  • Without posix-rename, the fallback is remove-then-rename and is not atomic.

Telemetry

Telemetry opens one exec channel on an existing session and reads /proc/stat, /proc/meminfo, /proc/net/dev, df output and, when the socket is readable by the login user, container status from the Docker Engine API on /var/run/docker.sock. Nothing is installed or left running on the host after the channel closes.

Latency, broadcast and recording

Each connected link sends a keepalive@openssh.com request every five seconds and reports the round trip, shown per host and in the status line. Input can be broadcast to a chosen group of terminals. Sessions can be recorded to asciicast v2; recordings contain output and resize events only, never keystrokes.

~/.ssh/config

Hosts can be imported from and written back to ~/.ssh/config. Edits preserve comments, ordering, indentation and every directive Citadel does not manage. Agent sockets are discovered from SSH_AUTH_SOCK, the 1Password and Bitwarden default locations, and the Windows OpenSSH agent named pipe.

04Sync

Sync is off until a target is configured. Citadel operates no servers; the storage provider only ever receives a sealed .ctdl blob.

BackendTransportConcurrency control
S3-compatibleHTTPS, SigV4, path-style or virtual-host addressingETag, conditional If-Match on write
WebDAVHTTPS, basic authenticationETag, conditional If-Match on write
GitThe system git and its credential setupRejected push triggers fetch, merge, retry
  1. Pull the remote blob. If it is sealed under the local data key, decrypt it directly. If not, ask for the password that sealed it, then rekey the local vault to that data key so every device converges on one key.
  2. Merge record by record. The newer timestamp wins; deletions are tombstones and propagate like any other record.
  3. Seal and push with the observed ETag. If another device wrote first, repeat from step 1.
  4. A password change bumps the header epoch. Devices that pull a newer header with the same data key adopt it, so the new password applies everywhere.

Credentials for sync targets are stored as encrypted vault records and replicate with the vault.

05The .ctdl container

Exports, imports and sync blobs share one format. All integers are little-endian. A file exported with a separate password carries a fresh data key wrapped by that password; a sync blob carries the vault's own wrapped key.

The decrypted payload is a u32 raw length followed by a single Zstandard frame. The frame decompresses to exactly that many bytes of MessagePack encoding a bundle { created_ms, entries }, where each entry is a host, identity, tunnel, snippet, known host, sync target or tombstone. Entries are sorted by id. Declared lengths above 64 MiB are rejected before decompression, and trailing data after the frame is an error.

06Performance

Measured with scripts/bench.sh, which runs the OpenSSH integration suite in release mode against an unprivileged sshd on loopback. Loopback figures measure CPU cost on both ends, not network throughput.

OperationPayloadMeanRangeRate
SFTP upload16 MiB134 ms123–151 ms106–130 MiB/s
SFTP download16 MiB64 ms56–72 ms221–286 MiB/s
Tunnel suite36 MiB282 ms240–340 msn/a

Five runs, 2026-10-23. Windows Subsystem for Linux 2 (kernel 6.6), Intel Core i7-13620H, OpenSSH 9.6p1 with its stock sftp-server. SFTP times include the remote fsync and the local file write. The tunnel figure is wall time for four concurrent 4 MiB echo streams through -L, 1 MiB through SOCKS5 and 1 MiB through -R, including sshd start-up and the handshake, with every byte compared on return.

Memory

The target is under 25 MB resident for the Rust core process. The system webview is not part of that figure: WebKitGTK and WebView2 run their own processes and WKWebView maps its own memory, and their footprint depends on the platform. Unlocking briefly allocates the 64 MiB Argon2 arena, which is cleared and freed as soon as the key is derived. The redb page cache is capped at 4 MiB.

From source

Requires Rust 1.90 or newer, Node.js 20 or newer and pnpm 10. On Linux, install the WebKitGTK development packages first:

sudo apt install libwebkit2gtk-4.1-dev libsoup-3.0-dev libjavascriptcoregtk-4.1-dev \
    libayatana-appindicator3-dev librsvg2-dev
git clone https://github.com/sepehrmohseni/citadel
cd citadel/app
pnpm install
pnpm tauri build

The crates build without the webview packages:

cargo test -p citadel-vault -p citadel-ssh -p citadel-telemetry -p citadel-config -p citadel-sync

To run the SSH suite against a real OpenSSH server, point it at sshd and sftp-server. The harness starts sshd as the current user on a random loopback port with generated keys:

CITADEL_SSHD=/usr/sbin/sshd \
CITADEL_SFTP_SERVER=/usr/lib/openssh/sftp-server \
cargo test -p citadel-ssh --test openssh
